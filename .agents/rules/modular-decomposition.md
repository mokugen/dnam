# Modular Decomposition, `AGENTS.md` Delegation & Co-Located Unit Tests

These architectural rules are mandatory for every code and documentation edit in DNAM:

1. **Decompose Large Functions, Components, Classes & Modules into Hierarchical Submodule Trees (`ref[repo.code.modular-decomposition-and-tests]`):**
   - **Break Up Large Monolithic Functions, Components & Wide Signatures:** Proactively decompose large monolithic functions, methods, React components/hooks, multi-stage pipelines, and deeply nested control/render trees (e.g., functions or components growing past `~80–120` lines or triggering `#[allow(clippy::too_many_arguments)]`, `#[allow(clippy::cognitive_complexity)]`, or Biome `complexity/noExcessiveCognitiveComplexity`) into small, named, single-purpose helper functions, custom hooks, sub-components, and cohesive domain/context types with invariants that can be reasoned about and unit-tested directly.
   - **Build Hierarchical Submodule Trees, Not Just Flat Siblings:** When a module grows beyond a single cohesive responsibility or approaches `~600–700` lines (well below `< 900` LOC ceilings), organize **production code** into **nested child submodules** rather than dumping flat `foo_bar` / `foo_baz` files into crowded parent directories or multi-thousand-line drivers:
     - **Rust (`packages/*/src/`, `packages/js/rust/`):** `src/<module>.rs` $\to$ `src/<module>/<sub_aspect>.rs` $\to$ `src/<module>/<sub_aspect>/<leaf>.rs` (zero `mod.rs`), using parent `.rs` files as clean facades encapsulating private child submodules.
     - **TypeScript / React / JS (`packages/js/src/`, `packages/ui/src/`, and downstream JS/TS packages — Zero Internal Barrel Files):** Decompose large modules and drivers into nested concrete leaf modules (`src/<domain>/<aspect>.ts(x)` $\to$ `src/<domain>/<aspect>/<leaf>.ts(x)`, or `<driver>.ts` + `<driver>/<domain>.ts`, `< 900` LOC ceiling) with **direct concrete leaf-module imports everywhere internally** (e.g., `../schema/header.js`, `./components/base/button.js`) and **zero internal barrel `index.ts` files or wildcard `export *`** (`lint/performance/noBarrelFile`, `lint/performance/noReExportAll`). Expose `@dnam-project/ui` (`packages/ui/`) exclusively via granular `package.json` subpath exports with zero barrels (`@dnam-project/ui/base/*` from `src/components/base/`, `@dnam-project/ui/{controls,rack,workflows,visualizers,host}/*`, `@dnam-project/ui/tokens`, `@dnam-project/ui/utils`). Allow explicit named re-exports (`export { ... }`) **strictly** on the declared public `package.json` `"exports"` entrypoints of `@dnam-project/dnam`, and forbid barrel files across all non-exported SDK folders (`model/`, `engine/`, `internal/native/{napi,wasm}/`) and all application packages (`web`, `plugin-ui`, `studio`, `cli`).
   - **Never Play Code Golf:** Never join multi-instruction inline assembly or statements with `\`-newline continuations (`\n\`), never pack multi-line expressions/JSX onto one line, avoid nested ternary chains, and never strip comments or docstrings/JSDoc to save lines.

2. **4-Tier Layered Testing Hierarchy — Rust & TypeScript/React/JS (`ref[repo.code.modular-decomposition-and-tests]`):**
   - **Tier 1 — Leaf Unit & Property Tests:**
     - **Rust (`src/<name>/<child>.rs`, `src/<name>/<child>/<leaf>.rs`):** Put unit tests and `proptest!` suites inside inline `#[cfg(test)] mod tests { ... }` at the bottom of the exact `.rs` production module they test (no blank line or attribute between `#[cfg(test)]` and `mod tests {`). If adding `#[cfg(test)] mod tests` pushes a module toward `~700–900` lines, **split the production code first** into clean submodules so each unit holds both its logic and co-located unit tests comfortably (`~250–650` lines total).
     - **TypeScript / React (`src/<domain>/<leaf>.test.ts(x)`, `<leaf>.browser.test.ts(x)`):** Co-locate leaf unit, `fast-check` (`fc.assert(fc.property(...))`), ARIA snapshot, and `axe-core` tests directly adjacent to `src/<domain>/<leaf>.ts(x)` (alongside `<component>.fixture.tsx` for React Cosmos components). Split any production module before it approaches `< 900` lines.
   - **Tier 2 — Parent / Domain Inter-Unit Integration Tests:**
     - **Rust (`src/<name>.rs`):** Smaller integration tests are allowed inside inline `#[cfg(test)] mod tests { ... }` in parent/facade `name.rs` files (`src/stimulus.rs`, `src/align.rs`, etc.) to test integration between the child units they encapsulate.
     - **TypeScript / React (`src/<domain>/<domain>.test.ts(x)`, `<domain>.browser.test.ts(x)`):** Keep domain-level suites inside `src/<domain>/` to test collaboration across concrete child modules within `<domain>` without introducing internal `index.ts` barrel files.
   - **Tier 3 — Package Integration & E2E Suites (`packages/<pkg>/tests/`):**
     - **Rust (`packages/<pkg>/tests/<domain>.rs`):** Keep package `tests/*.rs` strictly for cross-module / subsystem integration suites named after the domain or contract under test (with shared helpers in `tests/<domain>/*.rs`, never grab-bag `packages/*/tests/*_coverage.rs` files).
     - **TypeScript / React (`packages/<pkg>/tests/integration/<domain>.test.ts(x)`):** Keep package `tests/integration/`, `tests/profile/`, and `tests/e2e/*.spec.ts` strictly for cross-domain integration, N-API $\leftrightarrow$ WASM parity, browser/Playwright E2E, and profiling suites (never `*coverage*.test.ts(x)` grab-bag files).
   - **Tier 4 — Top-Level Workspace Tests (`tests/`):** Top-level `tests/` is the highest level of integration testing for monorepo-wide, cross-package, and guardrail integration suites (`moon check tests`).
   - **No Isolated / Unpaired Unit-Test Files or `__tests__` Directories in `src/`/`rust/`:**
     - **Rust:** **Never** create isolated unit-test `.rs` files inside `src/` or `rust/` (`tests.rs`, `*_tests.rs`, `test_*.rs`) or external `mod tests;` / `mod *_tests;` file declarations. Isolated test-only `.rs` modules are allowed **strictly for shared test helpers and builders** (`test_support.rs`, `test_utils.rs`, `testing.rs`, or helper submodules under `tests/<suite>/*.rs`).
     - **TypeScript / React / JS:** **Never** create `src/**/__tests__/` subdirectories, generic unpaired `src/**/test.ts(x)` / `src/**/tests.ts(x)` files, or `src/**/*.spec.ts(x)` files (reserve `*.spec.ts` for `tests/e2e/`). Shared TS test helpers belong in `test-support.ts`, `test-utils.ts`, `testing.ts`, or `packages/<pkg>/tests/setup.ts`.

3. **Never Wordsmith `AGENTS.md` to Fit Byte Budgets (`CONTRIBUTING.md` §5.1.3):**
   - When an `AGENTS.md` approaches `2,500 B`, create a scoped subdirectory `AGENTS.md` (`< 2,500 B`) and link it from the parent `AGENTS.md`, or offload non-routing prose to `packages/<pkg>/CONTRIBUTING.md` / `docs/specs/`. Never compress wording in `AGENTS.md` to squeeze rows.
